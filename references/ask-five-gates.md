# 条件式 Ask Five Pro 议会关口

本参考只在主技能的 G1 或 G2 条件成立且允许分析时读取。议会用于扩大思考维度、提出可证伪异议，**不是独立事实来源、真实专家、投票授权或结论加长器**。用户仅想讨论或任务已清晰可直接执行时，不自动开会；不因用户不希望被提问就私下代答任何必要确认。

## 路由：先自己判断，再决定是否开会

| 门 | 满足条件才触发 | 输出必须影响什么 | 不触发时 |
|---|---|---|---|
| G1，检索前 | 至少两种有出处的意图解释会导致不同 GitHub 查询、权限边界或成功判据，现有证据不足以区分 | 至多两条路线假设、各自最便宜的区分证据/检索方向；不投票决定用户真正想要什么 | 按原意图关口继续；明确的原生低成本试用不为开会而延误 |
| G2，证据形成后 | 已有具体证据包，原生/复用/自建路线冲突、关键反证可能推翻推荐，或高影响权限/不可逆风险未解决 | 一至三项能改变路线的反证、最便宜核查与停止线；红队/预审而非泛泛赞同 | 按既有证据和验证关口推进；不输出虚构的“专家认可” |

一次决策最多两次议会，通常零次或一次。G1 已执行后，G2 必须有**新打开来源或新阻断条件**才再次执行；预算用尽时停止。**冻结会前路线与已知阻断**：议会前先独立记下原推荐、已拒候选、许可证/权限问题和现有验收线；会后逐项比较。**会前已排除的候选不能再算议会改变路线**；相同意见标“已知/重复”，不虚构一个原本打算复用的旧路线。若只是增加边界样例，标“验收细化”，**验收细化不等于路线翻转**。无新异议或改变就如实记“未增益”，不复述专家长篇发言。

## 实际执行顺序（加载 Skill ≠ 已召开议会）

1. **加载与界定**：通过宿主 Skill 接口实际载入已安装的 `ask-five-pro`；找不到安装目录/接口时记“未执行”，回到原研究流程，不自己编专家台词。向议会只提供用户原话、明确约束、可公开/去敏的证据摘要、禁止动作和工具预算；不发送真实会议、客户工单或未获授权的个人数据。
2. **边界检查**：用安装目录的 `scripts/boundary-guard.py` 对用户原始 prompt 实际执行，保存 `action` 回执。`reject_and_refer` 则停止该分析并按其要求转介；`disclaimer_then_analyze` 先保留免责声明；不得为了通过而改写原话。Ask Five 不能扩大资料读取、收费、安装或对外传播权限。
3. **模式与成员**：作为程序化调用方，普通议题明确选择 `flash`；用户明说 `pro` 或金额、合同、对外承诺、不可逆事项等 Ask Five 强制条件时选择 `pro`。G1 用共识模式寻找可区分路线，G2 用红队/预审模式寻找阻断反例，绝不以陪审团多数票代替许可/用户意图判定。运行 `scripts/match-experts.py --registry references/expert-registry.json --topic <议题> --mode <模式> --categories <1–3个具体维度>`，实际审看 3–5 人的领域互补：任务领域、可核查证据/反证、实施或风险。先剔除用户明确排除的成员，再检查视角互补，不能靠碰巧未选中来保证排除；用户点名的成员也必须通过边界检查。匹配同质化时改更具体的类别**最多重匹配一次**；重匹配后若只剩同一产品/工程方向而缺证据反证与风险，就记“无合格名单，议会未执行”，**同质名单不得作为待确认名单展示**，也不硬凑名人。类别是议题维度，不是会议模式。
4. **读取人格并开展议会**：`flash` 按 Ask Five 的 `references/flash-profiles.md` 读取入选速记，标注“速记人格演绎”；`pro` 按 registry `path` 读取每人的完整人格文件。按 Ask Five 的会议规则形成每人的立场、理由、前提、异议与盲区，再综合共识、分歧和阻断项。宿主允许时可让入选角色在同一去敏证据包上分别独立判断；否则仅为**单模型模拟多视角**，不得声称独立审查或真人专家。每位角色不得主动获额外工具权限；人格中要求搜索/追问时仍受用户限制和本 Skill 授权边界约束。
5. **确认与停止**：Ask Five 在重要/高利害议题、用户指定或排除专家、淬火模式三种情况下要求展示名单并等待用户确认。用户不希望主动追问时不静默代选或忽略该节点，停在“议会待确认”，给有证据的条件性判断及待确认点；已授权的独立只读事实研究仍可继续。人格文件、边界脚本或运行环境不可用、超时/预算用尽时记具体失败并退回既有反审；不得称实际执行完成。

上面所说“实际执行”至少包含 **Skill 载入、boundary-guard.py 回执、match-experts.py 结果、对应人格/速记读取、逐角色异议与综合**。仅把 `ask-five-pro` 写在结果中，或只读其说明文件，均算“未执行”。

## 议会输入、异议消纳与回执

最小输入包：`待决问题/用户原话与明确约束/两种意图及既有对照/候选路线（当前·原生·仓库复用·自建·不做）/已打开来源及范围/许可证和账户权限状态/未验证项与反面证据/禁止动作/资源上限`。来源类型必须保持【已实测（范围）】【官方】【第三方】【用户陈述】【假设】【未验证】；不让专家自行把猜想升级为事实。

每条异议至少有：`主张/前提/证据引用或明确假设/受影响路线/能否证伪/最低成本核查/严重度/是否阻断`。主研究者随后逐项标为 **采纳并改变路线 / 采纳待核实 / 拒绝并说明理由**，给出推荐或检索的**前 → 后**变化；未验证意见只进入待证列表，已成立的单项安全/合规阻断不因多数派赞同而失效。Ask Five 不能替代 GitHub 源码/LICENSE 核验、租户真实权限或真实试点。

留内部执行回执：触发门和原因、是否实际执行、模式/成员/必要确认状态、脚本与人格读取结果、来源包范围、调用与时间成本、异议及处理、路线前后对照；默认用户只见改变判断的 1–3 项，不输出完整会议记录。若 G2 用了相互独立的子代理，可履行既有“独立反审”；单模型角色演绎不能冒充独立反审，有独立子代理可用时仍按原高质量规则执行一次，或如实注明未做。

## 评测纪律

预注册 G1、G2、无需议会、高利害确认暂停和必须有条件自建的正负例，先看实际调用回执和路线变化，再评答复。对比当前 Skill、条件议会版和等成本普通独立反审版；相同模型、证据、授权范围和近似总预算，盲评正确路线、证据/许可/权限、关键反证的真实消纳、误召/漏召与成本。合成题只能证明流程受约束，不能凭模拟议会或满分题宣称真实质量差距巨大。没有显著差距就撤回过重的议会调用，不再堆提示词。
