# 决策级研究与反证：高质量模式

只在用户明确要求深入研究/关键决策，或方案涉及跨团队、明显成本、外部权限、合规/数据风险时启用。低风险闲聊、明确执行任务和单点事实问答不运行此模式。**高质量不是更长的回答，而是改变推荐所需的事实被真的查过。**

## 先定判断门槛

用一句话写出待做决策；列最多 3 个能推翻初步建议的条件（例：没有该平台账号权限、用户已有原生能力、真实业务损失很小）。每个条件配可观察的成功/失败判据、可用证据和停止线。缺用户权限/真实行为就标未验证，不因已经研究很久而替用户做决定。

## 交叉核查而非单线搜集

从用户原话方案和另一个合理意图各跑一条检索线；每条至少查一项候选或现成替代、运行前提与许可证，深入程度按用户目标调整。额外看一次**不做/继续现有流程**会发生什么、谁承受成本。若候选是官方产品或商业方案，优先查其功能和账号/版本限制，不因 GitHub 必查而贬低原生方案。

跨团队或敏感数据场景还要把**读取/采集权限、加工用途权限、输出接收/再传播权限**分开核对：能够读取原始数据，不等于有权把跨人群汇总发给新的接收者。缺少任一环授权时，即便算法可用也不能进行真实数据试点或自动推送。

证据链分三层：①当前用户场景事实（亲述/记录/账户实测）；②公开技术证据（官方文档、仓库源码与实际许可证）；③推测与第三方报告。跨层推理必须说明条件，绝不以公开 Demo 冒充当前租户运行成功。最脆弱的一条论证主动寻找反例；如果反例成立，改变方案，而不是把它塞进“风险”脚注却不改结论。

## 决策前的反向审查

形成初稿后先看 [Ask Five G2 条件关口](ask-five-gates.md) 是否真的触发；若已由相互独立的子代理在同一去敏证据包上完成议会反审，可计作本节的一次独立反审，不重复开会。仅在单模型中扮演多位专家**不等于独立子代理**，不能声称独立复核；若工具和预算允许，仍由独立子代理做一次限定反审，否则自检并注明未独立复核。无论是否触发议会，只给审查者**用户原话、两种意图解释、已打开的来源及未验证项、草稿建议**，要求找 1–3 个可能改变路线的遗漏或反证，尤其检查推断冒充原话、README 冒充许可证或账户权限。审查者与议会都不是真实用户、不能替代来源或授权；有证据的意见必须修正结论，不能查证的意见只留待验证。纯讨论、低风险小任务不需要本步骤。

## 对用户的交付（先判断，后依据）

默认一屏可读：①现在更推荐什么、什么条件会使建议反转；②原始方案与真正目标之间的差别（仅有证据才断言）；③现有方案/改造/自建/不做的最相关对照；④决定结论的 1–3 条来源与证据级别；⑤最便宜的消疑实验、负责人或权限依赖、停止条件。深入附录仅用户需要时写，成本/周期没有依据不报精确数字。若任一关键条件缺证据，交付“条件性建议/暂待验证”，不要为报告完整而伪造肯定结论。

## 自检失败的标志

- 只把用户的方案说得更动听，没有解释另一条合理目标为何不成立。
- GitHub 候选的 README 已读，却没看 LICENSE/实际能力，或者把相似仓库当结论。
- 找到反证仍不改变建议；风险列表与结论脱节。
- 输出 20 条原则却没有最小测试、判断门槛或明确要谁做决定。
- 引用了独立审查者，却没有区分其假说与真实证据。
